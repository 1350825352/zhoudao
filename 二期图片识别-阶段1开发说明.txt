一、方案概述
--------------------------------------------------------------------------------
基于"知眸视频与图片任务完全解耦"的设计原则, 实现二期图片识别方案:
- 知眸图片任务: 异步创建任务 → 上报图片 → 等待回调 → 入库
- 自有模型识别: 同步调用 /api/v1/detect → 立即返回 → 入库
- 数据清洗: 同一张图片两边都有识别结果且目标位置匹配 → 判定为误识别

数据流:
  testimage 目录扫描 (后续替换为 MinIO 事件)
    ↓ 后端下载图片字节
    ├─→ 知眸: POST /api/task (创建) → POST /api/task/{id}/image (上报) → 异步回调 → 入 zhimou_image_detection
    └─→ 自有模型: POST /api/v1/detect (同步) → 入 self_model_image_detection
    ↓
  Redis 元数据反查 (taskId, frame.id) → local_image_name + GPS
    ↓
  数据清洗服务 → 中心点距离匹配 → 标记 clean_status (0/1/2)

六、关键技术决策
--------------------------------------------------------------------------------
6.1 知眸图片任务字段 (与视频任务不同)
  - app_ids (数组, 非单值 app_id)
  - zapk_id (非 application_package_id)
  - device_id (非 device)
  - report_url (顶层, 非嵌套 report.httpurl)

6.2 知眸图片上报 (image_id 关联机制)
  - 接口: POST /api/task/{task_id}/image?image_id=xxx&device_id=xxx
  - Body: application/octet-stream (二进制流)
  - 限制: 每任务最小上报间隔 1 秒
  - 关键: image_id 会在回调 data.frame.id 原样返回

6.3 Redis 元数据反查机制
  - 上报前: 写入 Redis Hash
    key: zhimou:img:meta:{taskId}:{imageId}
    value: {local_image_name, local_image_path, latitude, longitude, altitude}
    TTL: 24小时
  - 回调时: 用 frame.id 反查
    frame.id = image_id (知眸原样返回)
    meta key: zhimou:img:meta:{taskId}:{frame.id}

6.4 数据清洗算法
  - 误识别判定: 同一张图片两边都有识别结果 + 所有目标位置匹配 → 误识别
  - 位置匹配: bbox 中心点距离 < 50 像素 (DEFAULT_DISTANCE_THRESHOLD)
  - 知眸 bbox: {x, y} → 当前按"中心点"处理 (待实测确认)
  - 自有模型 bbox: {x1,y1,x2,y2} → center=((x1+x2)/2, (y1+y2)/2)

6.5 EXIF GPS 提取
  - 用 metadata-extractor 库从图片 EXIF 提取 GPS 信息
  - 同时存入两表, 方便后续按地理位置查询
