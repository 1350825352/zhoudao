本系统后端语言: Spring Boot 2.7 / JDK 17
配置文件: src/main/resources/application-company-a.yml

本文档供父系统对接使用，包含两个独立功能：
  功能1: 外部系统通过 API Key 换取 Token 调用本系统接口（父系统 → 本系统）
  功能2: 本系统清洗后向父系统推送识别告警数据（本系统 → 父系统）

两个功能完全独立，互不依赖，可单独对接。

================================================================================
功能1: 外部系统 API Key 换取 Token 认证
================================================================================

--------------------------------------------------------------------------------
1.1 背景
--------------------------------------------------------------------------------
本系统是父系统的子项目。父系统需要通过 token 调用本系统受保护接口。
不使用 JWT，复用现有 Redis token 机制（与前端登录 token 同一存储）。

--------------------------------------------------------------------------------
1.2 认证流程
--------------------------------------------------------------------------------
  父系统
    │
    │  ① POST /api/auth/api-key-login
    │     Headers: X-API-Key, X-API-Secret
    │  ──────────────────────────────►  本系统
    │                                      │ 校验 key/secret
    │                                      │ 生成 UUID token
    │                                      │ 存入 Redis (TTL 24h)
    │   ② 返回 { token, username, name, expiresIn } ◄──────
    │
    │  ③ 用 token 调本系统任意接口
    │     GET/POST /api/xxx?token=xxx
    │  ──────────────────────────────►  本系统
    │                                      │ Redis 查 token
    │                                      │ 滑动续期 24h
    │   ④ 返回业务数据 ◄──────────────────────
    │
    │  (token 过期，收到 401)
    │  ⑤ 自动重新执行 ① 换新 token
    │  ⑥ 用新 token 重发原请求

--------------------------------------------------------------------------------
1.3 换取 Token 接口
--------------------------------------------------------------------------------
接口名称: API Key 换取 Token
请求方式: POST
请求路径: /api/auth/api-key-login
Content-Type: application/json (请求体可空)

请求头 (Headers):
  X-API-Key:    {API Key}     必填，配置在 application-company-a.yml 的 external-auth.api-key
  X-API-Secret: {API Secret}  必填，配置在 external-auth.api-secret

默认凭据（可改）:
  api-key:    zhoudao-parent-key
  api-secret: a8f3b2c1d9e7f0a5

请求体: 可空（POST 无 body 即可）

响应 (HTTP 恒为 200, application/json):
  注意: 本系统所有失败场景 HTTP 状态码均为 200, 失败信息放在响应体 code 字段
  父系统必须解析响应体 code 判断成功失败, 不要按 HTTP 状态码判断

成功:
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "78eba9ccbfd94156ab8b1234567890ab",
    "username": "external-system",
    "name": "外部系统",
    "expiresIn": 86400
  },
  "success": true
}

失败 (key/secret 错误):
{
  "code": 401,
  "msg": "API Key或Secret错误",
  "data": null,
  "success": false
}

失败 (未配置):
{
  "code": 500,
  "msg": "API Key认证未配置",
  "data": null,
  "success": false
}

字段说明:
  token     - 32位 UUID（无横线），后续调本系统接口用
  username  - 固定 "external-system"
  name      - 固定 "外部系统"
  expiresIn - token 有效期秒数（86400 = 24小时）

--------------------------------------------------------------------------------
1.4 Token 验证接口（可选，用于父系统启动时自检）
--------------------------------------------------------------------------------
请求方式: GET
请求路径: /api/auth/verify?token={token}

响应 (成功):
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 0,
    "username": "external-system",
    "name": "外部系统",
    "dept": "信息中心"
  }
}

响应 (token 过期/无效):
{
  "code": 401,
  "msg": "登录已过期，请重新登录"
}

权限说明:
  外部系统 token 自动拥有 hasAdminAccess=true，
  可访问本系统管理后台（admin-v3）所有接口。
  滑动续期: 每次 verify 成功，TTL 重置为 24 小时。

--------------------------------------------------------------------------------
1.5 Token 过期处理（父系统侧实现建议）
--------------------------------------------------------------------------------
推荐方式: 过期重换
伪代码:
  function callSikongApi(url, params):
      resp = http(url + "?token=" + cachedToken)
      if resp.code == 401:                          # token 过期
          cachedToken = apiKeyLogin()                # 重新换 token
          saveToken(cachedToken)                     # 缓存新 token
          resp = http(url + "?token=" + cachedToken) # 用新 token 重发
      return resp

  function apiKeyLogin():
      resp = httpPost("/api/auth/api-key-login", headers={
          "X-API-Key":    "zhoudao-parent-key",
          "X-API-Secret": "a8f3b2c1d9e7f0a5"
      })
      return resp.data.token

--------------------------------------------------------------------------------
1.6 父系统登录前端页面 (token URL 登录)
--------------------------------------------------------------------------------
父系统拿到 token 后, 可直接通过 URL 参数登录本系统的前端页面, 无需再走用户名密码登录.

登录 URL 格式:
  大屏(screen-v3): http://192.168.2.130:3202/#/?token={token}
                   或 http://192.168.2.130:3202/?token={token}
  后台(admin-v3):  http://192.168.2.130:3201/#/?token={token}

token 来源: 1.3 节 api-key-login 接口返回的 data.token 字段

工作原理:
  - 前端在启动时检测 URL 上的 token 参数 (支持 search 和 hash 两种格式)
  - 验证通过后自动写入 sessionStorage, 建立登录态
  - 登录成功后 URL 上的 token 会被自动清除 (history.replaceState), 避免泄露

注意事项:
  - token 有 24 小时 TTL, 过期后 URL 登录会失败, 需重新换取 token
  - 同一 token 可同时用于 screen 和 admin 登录
  - admin 需要 hasAdminAccess=true 权限, API Key 换取的 token 默认有此权限
  - 父系统可用 iframe 嵌入或 window.open 新窗口打开上述 URL

1.7 测试命令 (PowerShell)
--------------------------------------------------------------------------------
# 1. 换取 token
$headers = @{
    "X-API-Key"    = "zhoudao-parent-key"
    "X-API-Secret" = "a8f3b2c1d9e7f0a5"
}
$resp = Invoke-WebRequest -Uri "http://192.168.2.130:8080/api/auth/api-key-login" `
    -Method POST -Headers $headers -UseBasicParsing

# 期望: {"code":200,...,"token":"xxx",...}

# 2. 验证 token
$token = ($resp.Content | ConvertFrom-Json).data.token
Invoke-WebRequest -Uri "http://192.168.2.130:8080/api/auth/verify?token=$token" `
    -Method GET -UseBasicParsing | Select-Object StatusCode, Content
# 期望: {"code":200,...,"name":"外部系统",...}

# 3. 错误 key 测试
# 注意: 本系统失败场景 HTTP 状态码恒为 200, 错误信息放在响应体 code 字段
# 不要用 try/catch 捕获 HTTP 异常, 应解析响应体 code 字段判断成功失败
$resp = Invoke-WebRequest -Uri "http://192.168.2.130:8080/api/auth/api-key-login" `
    -Method POST -Headers @{"X-API-Key"="wrong";"X-API-Secret"="wrong"} `
    -UseBasicParsing
$resp.StatusCode     # 200 (HTTP 恒为 200)
$resp.Content        # {"code":401,"msg":"API Key或Secret错误"}
# 判断成功失败: 解析响应体 code 字段, 200 才算成功
($resp.Content | ConvertFrom-Json).code   # 401

================================================================================
功能2: 清洗后异步推送识别告警数据到外部接口
================================================================================

--------------------------------------------------------------------------------
2.1 背景
--------------------------------------------------------------------------------
知眸图片识别结果清洗完成后，本系统主动向父系统 POST 推送告警数据。
推送数据包含经纬度、高度、应用名、标注图访问 URL 等。

推送方向: 本系统 ──► 父系统接收接口
推送方式: 异步并行（每条独立线程，互不等待）
内网环境，无需鉴权头（如需，可扩展 push 配置加 auth-header）

--------------------------------------------------------------------------------
2.2 推送时机
--------------------------------------------------------------------------------
触发: ImageCleanupService 清洗完成，写入 clean_status 后
过滤: 只推 clean_status = 1 (真实告警)
       不推 clean_status = 2 (误识别)
       不推 clean_status = 0 (未清洗/无目标)
开关: push.enabled = true 时才推 (yml 配置)

--------------------------------------------------------------------------------
2.3 推送数据格式（父系统需实现的接收接口）
--------------------------------------------------------------------------------
接收接口要求:
  请求方式: POST
  Content-Type: application/json
  超时: 3 秒（本系统侧配置，父系统应 < 3 秒返回）
  无鉴权头（内网信任）

确认机制 (confirm-mode: code0):
  父系统返回 HTTP 200 + {"code":0,"message":"ok"}  → 推送成功
  父系统返回非 200 / 超时 / 响应体不含 code:0        → 进入重试

确认机制 (confirm-mode: http200, 降级模式):
  父系统返回 HTTP 200 即视为成功

推送数据 (JSON Body):
{
  "aircraft_sn": "1581F8HGX252F00A018X",              # 飞机SN
  "task_id": "1587912981127494992",                   # 知眸任务ID
  "image_name": "20e8c0db-86c4-4015-b983-6dfbbb011e5c/DJI_20260831181515_0001_V",  # 本地图片名(含UUID目录前缀, 清洗关联键)
  "latitude": 32.0602550,                             # 纬度(最多7位小数)
  "longitude": 118.796877,                            # 经度
  "altitude": 85.5,                                   # 高度(米)
  "app_name": "小客车识别",                            # 知眸应用名
  "hit_count": 10,                                    # 识别目标数
  "clean_status": 1,                                  # 1=真实告警(固定)
  "clean_remark": "正常:知眸11个目标中10个匹配自有模型", # 清洗说明
  "annotated_image_url": "http://192.168.2.130:8080/api/image-detect-img/20260831/xxx/annotated/DJI_xxx.jpg",
  "detect_time": "2026-08-31 17:12:42"                # 识别时间
}

字段说明:
  aircraft_sn        - 飞机设备SN
  task_id           - 知眸任务ID (字符串)
  image_name        - 图片本地文件名, 含UUID目录前缀 (如 20e8c0db-.../DJI_xxx_V)
                      说明: 该前缀是本系统数据清洗关联键, 父系统按 opaque 字符串存储即可,
                      请勿按 "/" 拆分或截取, 直接整串用于关联/去重
  latitude          - 纬度 (BigDecimal, 最多7位小数, 精度约0.01米)
  longitude         - 经度 (BigDecimal, 最多7位小数, 精度约0.01米)
  altitude          - 相对高度 (米)
  app_name          - 知眸应用名 (小客车识别/人员识别等)
  hit_count         - 命中目标数 (整数)
  clean_status      - 固定 1 (推送的都是真实告警)
  clean_remark      - 清洗结果描述
  annotated_image_url - 标注图访问URL (带检测框的图片)
                       格式: http://{host}:{port}/api/image-detect-img/{path}
                       父系统可直接 GET 访问该 URL 查看带框图片
  detect_time       - 识别时间 (yyyy-MM-dd HH:mm:ss)

注意:
  - detect_time 是字符串格式 "yyyy-MM-dd HH:mm:ss", 不是毫秒时间戳
  - 同一张图片可能有多个识别结果（如汽车+人员），会分多条推送
  - 一批 15 张图清洗后可能产生多条 clean_status=1 记录，并行推送
  - annotated_image_url 可能为 null (无标注图时)

2.5 重试机制
--------------------------------------------------------------------------------
本系统侧重试逻辑:
  超时时间: 3 秒 (push.timeout, 单次请求)
  最大推送: 3 次 (push.max-retries)
  重试间隔:
    第1次失败 → 等 3 秒 → 第2次推送
    第2次失败 → 等 5 秒 → 第3次推送
    第3次失败 → 记录 ERROR 日志 (含推送 payload，方便人工补推)

最坏情况时间线 (3次都失败):
  0s    第1次推送 (3秒超时) → 失败
  6s    第2次推送 (3秒超时) → 失败 (等3秒后发)
  14s   第3次推送 (3秒超时) → 失败 (等5秒后发) → 记录 ERROR 日志
  总计 17 秒兜底完毕

正常情况 (第1次就成功):
  < 100ms 完成

并行推送:
  10 条消息各自独立异步线程推送，互不等待
  正常情况 10 条 < 1 秒全部完成
  最坏情况 10 条 17 秒全部兜底完毕

实现:
  PushService 使用 @Async (Spring 异步) + ScheduledExecutorService (重试调度)
  不引入 MQ，轻量级方案

2.7 配置（application-company-a.yml）
--------------------------------------------------------------------------------
push:
  enabled: false                                      # 推送开关 (false=不推)
  url: "http://192.168.2.130:9090/api/receive"         # 父系统接收地址
  timeout: 3000                                        # 单次请求超时(毫秒)
  max-retries: 3                                       # 最大重试次数
  retry-delays: [3000, 5000]                           # 重试间隔(毫秒) [第1次,第2次]
  confirm-mode: "code0"                                # 确认模式 code0|http200

修改后需重启后端生效。

注意:
  - enabled 默认 false，测试推送前需改为 true
  - url 需改为父系统实际接收地址
  - 父系统接收接口需返回 {"code":0} 确认，否则会触发重试
