2. 开关控制测试
================================================================================

【测试2.1】image_task=0（关闭）时轮询跳过
  前置：
    Redis 或 DB 中 image_task = 0
    MinIO 中有未处理的飞行批次
  步骤：
    1. 确认 image_task=0
       Redis: GET task_switch:image_task  → "0"
       或 DB: SELECT value FROM task_switch WHERE switch_key='image_task'
    2. 等待 30s（一个轮询周期）
    3. 查 Redis: KEYS minio:flight:*
  预期：
    - 控制台输出 [MinIO轮询] image_task 已关闭，本轮跳过
    - Redis 中无 minio:flight:* 任何 key（未处理任何批次）
  实际：________________________________

【测试2.2】image_task=1（开启）时轮询执行
  前置：
    image_task = 1
    MinIO 中有未处理的飞行批次（如 dbc84414...）
  步骤：
    1. 设置 image_task=1
       Redis: SET task_switch:image_task 1
    2. 等待 30s 或手动 POST /api/minio/scan-now
  预期：
    - 控制台输出 [MinIO轮询] 扫描到 1 个候选飞行任务批次

10. 自动清洗触发测试（核心！）
================================================================================

  这是阶段3最核心的功能：知眸回调 + 自有模型入库两边到齐后自动清洗。
  需要分别测试"知眸先到"和"自有先到"两种时序。

【测试10.1】自有模型先入库，知眸回调后到 → 自动清洗
  前置：
    image_task=1
    MinIO 有 dbc84414... 批次（15张图）
  步骤：
    1. POST /api/minio/scan-now
    2. 等待自有模型处理完成（约 8s）
    3. 查 Redis: GET minio:flight:img:dbc84414.../DJI_..._0001_V
       预期 hash 中有 self=1，无 zhimou（知眸回调还没来）
    4. 等待知眸回调到达（约 1-5s 后）
    5. 查日志
  预期：
    - 日志 [知眸-图片回调] 入库成功 ... localImageName=dbc84414.../DJI_..._0001_V
    - 日志 [自动清洗] ⭐ 知眸与自有模型结果均到齐 → 启动 cleanup localImageName=dbc84414.../DJI_..._0001_V
    - 日志 [清洗] 完成 localImageName=dbc84414.../DJI_..._0001_V, 结果=..., cleanStatus=1或2
    - Redis: minio:flight:img:dbc84414.../DJI_..._0001_V 已被 DELETE
    - DB: zhimou_image_detection.clean_status != 0
    - DB: self_model_image_detection.clean_status != 0
  验证命令：
    Redis: EXISTS minio:flight:img:dbc84414.../DJI_20260826130711_0001_V  → 0 (已删)
    MySQL: SELECT local_image_name, clean_status, clean_time, clean_remark
           FROM zhimou_image_detection
           WHERE local_image_name LIKE 'dbc84414%' AND deleted=0;
    MySQL: SELECT local_image_name, clean_status, clean_time, clean_remark
           FROM self_model_image_detection
           WHERE local_image_name LIKE 'dbc84414%' AND deleted=0;
  实际：________________________________

【测试10.2】知眸回调先到，自有模型后入库 → 自动清洗
  前置：
    知眸处理速度 > 自有模型（理论上知眸回调通常在1s内到达）
  步骤：
    1. POST /api/minio/scan-now
    2. 等待知眸回调到达（日志 [知眸-图片回调] 入库成功）
    3. 查 Redis: GET minio:flight:img:dbc84414.../DJI_..._0001_V
       预期 hash 中有 zhimou=1，无 self（自有还没入库）
    4. 等待自有模型入库（约 0.5s 后）
    5. 查日志
  预期：
    - 日志 [自有模型] 入库 ... localImageName=dbc84414.../DJI_..._0001_V
    - 日志 [自动清洗] ⭐ 自有模型与知眸结果均到齐 → 启动 cleanup
    - 清洗结果同 10.1
  实际：________________________________

【测试10.3】全部 15 张图都自动清洗完成
  前置：批次 15 张图全部处理完
  步骤：
    1. 等待所有知眸回调和自有模型入库完成
    2. 检查 DB 和 Redis
  预期：
    - 15 条 zhimou_image_detection 的 clean_status 全部 != 0
    - 15 条 self_model_image_detection 的 clean_status 全部 != 0
    - Redis: KEYS minio:flight:img:dbc84414...* → 空（全部已清理）
  验证命令：

  实际：________________________________

  步骤：
    1. 等待 30s（自动轮询触发）或 POST /api/minio/scan-now
    2. 观察日志依次出现：
       a. [MinIO轮询] 扫描到 1 个候选飞行任务批次
       b. [MinIO轮询] ✅ 拿到处理锁 taskUuid=..., 图片数=15, TTL=1800s
       c. [MinIO轮询] taskUuid=... 飞行任务名=..., SN=1581F8HHX25CL00A06BL
       d. [MinIO轮询] 下载 taskUuid=... 成功=15/失败=0
       e. [知眸-图片批量上报] 创建任务成功 taskId=..., 待上报图片数=15, prefix=dbc84414...
       f. [自有模型] 调用完成 fileName=..., 耗时=...ms
       g. [MinIO轮询] ✅ 分派完成 taskUuid=..., 图片数=15, zhimouTaskId=tsk_..., self(成功/失败)=15/0
       h. [知眸-图片回调] 入库成功 ... localImageName=dbc84414.../DJI_..._0001_V
       i. [自动清洗] ⭐ 知眸与自有模型结果均到齐 → 启动 cleanup localImageName=dbc84414.../DJI_..._0001_V
       j. [清洗] 完成 localImageName=..., 结果=..., cleanStatus=1或2
       k. [MinIO批次] ✅ 标记 COMPLETED taskUuid=dbc84414...
       l. [MinIO批次] 删除临时下载目录 ... result=true
    3. 检查 Redis:
       - GET minio:flight:dbc84414... → "COMPLETED"
       - KEYS minio:flight:img:dbc84414...* → (empty)
    4. 检查 MySQL:
       - SELECT COUNT(*) FROM zhimou_image_detection
         WHERE local_image_name LIKE 'dbc84414%' AND clean_status != 0;
         期望 15
       - SELECT COUNT(*) FROM self_model_image_detection
         WHERE local_image_name LIKE 'dbc84414%' AND clean_status != 0;
         期望 15
    5. 前端切换 alert_data_source=image
    6. 查看 screen-v3 /alerts 页面

  预期：
    - 所有 15 张图 clean_status=1 或 2（无一为 0）
    - 前端正常展示 clean_status=1 的告警
    - tempDir 已清理
    - Redis 批次 COMPLETED
    - 下一轮轮询自动跳过该批次
